# AI Image Studio 图片编辑器重构方案

> 版本：V1.0
>
> 日期：2026-08-05
>
> 状态：V1 核心能力已实现
>
> 产品主对标：稿定设计
>
> 技术底座：Vue 3 + TypeScript + Konva

## 1. 背景

AI Image Studio 已具备会话式生图、历史作品、原图下载和基于 Cropper.js 的矩形裁剪能力。当前裁剪功能位于 `ImageCropModal.vue`，具备以下特点：

- 从创作台和历史作品进入；
- 在原图内部拖动矩形选区；
- 右侧输入原图像素宽高；
- 浏览器基于原图选区导出 PNG、JPEG 或 WebP；
- 不缩放裁剪结果，不保存编辑状态；
- 无独立输出画布、背景、图层、撤销重做和 AI 扩图。

用户反馈表明，生图后仍需把图片导入稿定设计，才能完成目标尺寸、主体位置和最终构图。这不是单个裁剪框的精度问题，而是当前产品只支持“从原图中截取区域”，没有“以最终成品画布为中心进行设计”的能力。

本次重构的目标是把现有裁剪弹窗升级为轻量、非破坏性的图片编辑器，使用户从生成图片到导出可发布成品的流程在 AI Image Studio 内闭环完成。

## 2. 决策摘要

本方案确定以下方向：

1. 产品主对标稿定设计的画布与尺寸体系，交互简洁性参考 Canva，专业术语参考 Photoshop/Photopea，AI 画布参考 InvokeAI。
2. 不继续以 Cropper.js 作为编辑器核心，使用 Konva 建立统一的画布、元素、变换和裁剪模型。
3. 编辑器使用独立全屏路由，不再把复杂编辑能力堆叠在预览弹窗中。
4. 严格区分“原图尺寸”“裁剪选区”“成品画布尺寸”和“导出尺寸”。
5. 原始 Asset 永远只读；所有编辑采用参数化、非破坏性保存，导出结果保存为新的 Asset。
6. 第一阶段优先实现能够替代稿定裁剪流程的确定性能力；AI 扩图按 Provider/模型能力在后续阶段启用。
7. 宽高默认不联动，比例锁定必须由用户显式开启；任何输入都不得被静默改写。
8. 预览只负责显示，最终导出必须读取原始 Asset 并按真实像素渲染。

### 2.1 V1 实现结果

- 已新增 `/editor/:assetId` 全屏编辑器路由，创作台和历史作品均已切换到“编辑成品”；
- 已采用 Konva `10.3.0`（MIT）实现画布、原图裁剪、元素变换、视口缩放和安全区；
- 已实现宽高默认独立、显式比例锁定、Cover/Contain/Free/Stretch、九宫格锚点、透明/纯色/模糊背景、撤销重做和恢复；
- 已新增版本化编辑文档、乐观并发保存、空闲自动保存、未保存离开保护和刷新恢复；
- 已实现从原始 Asset 重新解码的 PNG/JPEG/WebP 确定性导出，服务端复核真实格式和像素尺寸后保存派生 Asset；
- 已把图片任务泛化为会话或编辑器两种互斥上下文，并按模型显式能力门控 AI 扩图；
- 已移除 Cropper.js、旧裁剪组件及旧入口。

## 3. 产品定位

重构后的产品定位不是“带裁剪功能的生图平台”，而是：

> 用户完成生图后，可以直接制作并导出适合发布、投放、电商和社交媒体使用的最终成品。

编辑器应覆盖以下核心场景：

- 将正方形生图制作成横版、竖版或任意自定义尺寸；
- 调整人物或商品在目标画布中的位置和大小；
- 在不拉伸主体的情况下选择填满画布或完整显示；
- 用透明、纯色或模糊背景填补空白；
- 保留原图清晰度，准确导出指定像素尺寸；
- 保存编辑状态，稍后继续修改；
- 在模型支持时，对画布缺失区域进行 AI 扩图；
- 将同一张图片批量适配多个常用平台尺寸。

## 4. 范围与非目标

### 4.1 本次重构范围

- 独立图片编辑器页面；
- 成品画布和图片元素分离；
- 原图裁剪、画布适配和自由布局；
- 自定义宽高、比例预设和显式比例锁定；
- 图片移动、缩放、旋转、翻转；
- 背景填充；
- 撤销、重做和恢复原图；
- 编辑文档保存与恢复；
- 高清导出并保存为新 Asset；
- AI 扩图接口和能力门控；
- 创作台、历史作品与编辑器的完整跳转链路。

### 4.2 非目标

首轮重构不建设通用 Photoshop，不包含：

- 视频编辑；
- 多人实时协作；
- 第三方插件市场；
- CMYK、印刷色彩管理和专业印前流程；
- 任意复杂矢量路径编辑；
- PSD 导入导出；
- 无限图层和大型排版工程；
- 未经能力验证的通用 AI 局部编辑。

## 5. 核心概念

| 概念 | 定义 | 是否修改原图 |
|---|---|---|
| 原图尺寸 | Asset 文件解码后的真实像素宽高 | 否 |
| 裁剪选区 | 原图坐标系中的 `x/y/width/height` | 否 |
| 图片元素 | 原图在成品画布中的位置、缩放、旋转和裁剪状态 | 否 |
| 成品画布 | 最终作品的宽高、背景和安全区域 | 否 |
| 预览视口 | 浏览器中用于查看画布的缩放和平移状态 | 否 |
| 导出尺寸 | 输出文件的真实像素宽高，默认等于成品画布 | 生成新 Asset |

禁止把预览视口尺寸作为裁剪或导出尺寸。屏幕上的 `1px` 不得被解释为原图的 `1px`。

## 7. 工具与交互设计

### 7.1 原图裁剪

用途：直接截取原图中的一块区域，不改变选区像素。

能力：

- 自由裁剪；
- `1:1`、`4:3`、`3:4`、`16:9`、`9:16` 等比例预设；
- 自定义比例；
- 精确输入 `X`、`Y`、宽、高；
- 比例锁定开关，默认关闭；
- 拖动选区与输入字段双向同步；
- 输入字段聚焦期间以用户草稿为权威，不接受画布事件反写；
- 无效值保留并显示错误，不静默纠正；
- 支持居中、恢复完整原图和旋转后裁剪。

裁剪模式默认导出尺寸等于裁剪选区尺寸，不进行重采样。

### 7.2 画布适配

用途：先确定最终成品尺寸，再决定原图如何放入画布。

用户输入最终画布宽高后，提供以下策略：

| 策略 | 行为 | 是否裁掉原图 | 是否拉伸 |
|---|---|---:|---:|
| 填满画布 | 保持比例放大，超出画布部分被裁掉 | 是 | 否 |
| 完整显示 | 保持比例缩放，整张图片都可见 | 否 | 否 |
| 自由布局 | 用户自行移动、缩放和旋转图片 | 可选 | 否 |
| 拉伸填满 | 图片直接缩放到画布尺寸 | 否 | 是 |

“拉伸填满”必须明确标注可能变形，不作为默认选项。

画布尺寸支持：

- 自定义宽高；
- 交换宽高；
- 显式比例锁定；
- 常用比例；
- 场景尺寸预设，如公众号头图、小红书、抖音封面、电商主图等；
- 主体对齐：居中、上、下、左、右和九宫格锚点；
- 安全区与参考线。

### 7.3 图片变换

- 拖动移动；
- 控制点等比缩放；
- 按住 `Shift` 切换临时缩放约束；
- 旋转角度输入和拖动旋转；
- 水平/垂直翻转；
- 一键居中；
- 一键适配宽度、适配高度、填满画布；
- 可选主体焦点，智能适配时优先保留焦点区域。

### 7.4 背景

第一阶段支持：

- 透明背景，仅 PNG/WebP 可用；
- 纯色背景；
- 从图片取色；
- 模糊原图背景。

后续支持：

- 渐变背景；
- 上传背景图；
- AI 背景；
- 商品图阴影和投影。

### 7.5 AI 扩图

AI 扩图不是普通裁剪的兜底，而是独立工具：

1. 用户设置目标画布尺寸；
2. 原图作为只读主体放入画布；
3. 系统生成画布外部区域的蒙版；
4. 用户可输入扩图提示词，也可留空让模型延续环境；
5. 服务端创建图片编辑任务；
6. 生成结果作为新的 Asset 返回编辑器；
7. 用户可对结果继续布局、重试或恢复原图。

仅当模型能力明确声明支持图片编辑及所需输入形式时显示 AI 扩图。不得因为 Provider 存在 `edit` 方法就推断所有模型支持蒙版或严格尺寸。

模型能力至少需要表达：

```ts
interface ImageEditCapability {
  supportsImageEdit: boolean
  supportsMask: boolean
  supportsOutpaint: boolean
  supportedInputMimeTypes: string[]
  supportedOutputSizes: string[] | 'custom' | 'auto'
  maxInputImages: number
  maxDimension: number | null
}
```

若模型不能严格返回目标尺寸，服务端必须把生成结果视为扩图素材，由确定性合成流程裁切或合成到目标画布；不能直接把模型输出尺寸当成成功标准。

### 7.6 撤销、重做与保存

- 所有文档修改必须生成可撤销命令；
- 连续拖动只在拖动结束时形成一个历史步骤；
- 连续输入可按一次编辑会话合并；
- 默认保留最近 100 个本地历史步骤；
- 撤销历史不要求首阶段服务端持久化；
- 文档最新状态必须可保存到服务端；
- 页面离开前若有未保存修改，需要确认；
- 自动保存采用空闲触发，不在每个指针移动事件中请求服务端。

## 8. 产品行为规则

### 8.1 尺寸输入

1. 输入框允许用户连续输入，不用中间值触发回写。
2. 宽和高相互独立，默认不联动。
3. 开启比例锁定后，只根据用户正在修改的边计算另一边。
4. 无效输入保持原样并显示具体原因。
5. 失焦和 Enter 不得读取画布值覆盖用户输入。
6. 合法输入在下一帧内反映到画布，不使用可感知防抖。
7. 只有用户主动拖动画布对象时，才用画布结果同步非编辑状态的输入框。

### 8.2 边界与错误

- 裁剪选区不得超出原图；
- 图片元素可以超出成品画布，由画布裁切显示；
- 目标画布大于原图不是错误，按当前适配策略处理；
- 透明背景导出 JPEG 时必须要求改用 PNG/WebP 或选择填充色；
- 超过最大尺寸或总像素限制时保留输入并显示限制；
- 导出失败不得丢失编辑状态；
- AI 扩图失败不得替换当前图片元素。

### 8.3 清晰度

- 预览图片可缩放显示，但不得生成低分辨率中间文件替代原图；
- 导出时重新读取原始 Asset；
- 纯裁剪模式不得重采样；
- 需要缩放时使用高质量重采样；
- 任何放大都必须明确提示“放大不会创造原图细节”；
- AI 超清属于独立能力，不与普通导出混淆。

## 9. 技术架构

### 9.1 总体结构

```text
原始 Image Asset
       │
       ▼
Editor Document ─────► Konva Scene ─────► 浏览器预览
       │                    │
       │                    └────────────► 用户交互事件
       │
       ├──────────────► Deterministic Exporter ─────► Derived Asset
       │
       └──────────────► AI Edit Task ───────────────► Generated Asset
```

### 9.2 前端模块

建议新增：

```text
frontend/src/features/image-editor/
├── ImageEditorView.vue       页面容器、加载与保存
├── EditorCanvas.vue          Konva Stage、Layer 和交互
├── EditorToolbar.vue         工具切换
├── EditorInspector.vue       右侧属性面板
├── editorDocument.ts         文档类型、默认值、校验与迁移
├── editorStore.ts            当前文档、选择、历史和保存状态
├── coordinates.ts            原图/场景/视口坐标转换
├── fitStrategies.ts          cover/contain/free/stretch 计算
└── exporter.ts               基于原图的确定性导出
```

组件数量在实现时可按实际复杂度合并，不为单次逻辑创建无意义抽象。

### 9.3 Konva 场景

第一阶段保持最小场景树：

```text
Stage                        预览视口
└── WorkspaceLayer
    ├── CanvasBackground     成品画布背景
    ├── ImageGroup           受成品画布 clip 限制
    │   └── SourceImage      原图元素
    ├── SelectionTransformer 控制点
    └── Guides               参考线和安全区
```

视口缩放通过 Stage 或 WorkspaceLayer 完成，不能写回文档中的图片缩放。文档变换和查看变换必须完全分离。

### 9.4 坐标体系

编辑器包含三套坐标：

1. Source：原图真实像素；
2. Document：成品画布坐标；
3. Viewport：屏幕预览坐标。

转换关系：

```text
documentPoint = inverse(viewportTransform) × screenPoint
sourcePoint   = inverse(imageTransform) × documentPoint
screenPoint   = viewportTransform × imageTransform × sourcePoint
```

所有指针拖动先转换到 Document 坐标。裁剪框保存 Source 坐标。屏幕 CSS 像素不能直接参与尺寸校验。

### 9.5 适配算法

对于原图 `sourceWidth × sourceHeight` 和画布 `canvasWidth × canvasHeight`：

```ts
const coverScale = Math.max(
  canvasWidth / sourceWidth,
  canvasHeight / sourceHeight,
)

const containScale = Math.min(
  canvasWidth / sourceWidth,
  canvasHeight / sourceHeight,
)
```

`cover` 使用较大比例并由画布裁掉超出区域；`contain` 使用较小比例并由背景填补剩余区域。内部保存浮点数，只在像素导出边界进行确定性取整。

## 10. 编辑文档模型

首阶段采用版本化 JSON 文档，避免为每一种工具建立独立数据库字段。

```ts
interface ImageEditorDocumentV1 {
  schemaVersion: 1
  canvas: {
    width: number
    height: number
    background: {
      type: 'transparent' | 'color' | 'blurred-image'
      color?: string
      blurRadius?: number
    }
  }
  layout: {
    fitStrategy: 'cover' | 'contain' | 'free' | 'stretch'
    anchor: 'top-left' | 'top' | 'top-right' | 'left' | 'center' | 'right' | 'bottom-left' | 'bottom' | 'bottom-right'
  }
  image: {
    assetId: string
    x: number
    y: number
    scaleX: number
    scaleY: number
    rotation: number
    flipX: boolean
    flipY: boolean
    crop: {
      x: number
      y: number
      width: number
      height: number
    }
  }
}
```

首阶段只支持一个主图片元素，避免为了未来多图层提前复杂化。Schema 保留版本号；增加文字、贴纸和多图片时再迁移为 `elements[]`，不在 V1 预埋未使用字段。

文档 ID、初始 Source Asset、标题、版本和时间戳由 `image_edit_documents` 表管理，API 响应把这些资源元数据与 `document` 一起返回，不在 JSON 文档内部重复保存。

文档中不保存：

- 图片 Base64；
- Local 绝对路径；
- S3 签名 URL；
- 浏览器 Blob URL；
- 预览视口缩放；
- 临时 Transformer 状态；
- Provider Secret。

## 11. 后端与数据模型

### 11.1 原则

- 沿用现有 Local/S3 Image Asset 存储；
- Source Asset 不可被编辑覆盖；
- 导出结果是新的 Image Asset；
- 编辑文档归当前用户所有；
- 服务端继续校验输出文件格式、真实宽高和像素上限；
- 所有 Asset 访问保持 owner 范围和当前认证规则。

### 11.2 建议表

新增 `image_edit_documents`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 文档 ID |
| `owner_id` | UUID | 所属用户 |
| `source_asset_id` | UUID | 初始原图 Asset |
| `title` | TEXT | 文档名称 |
| `schema_version` | INTEGER | JSON Schema 版本 |
| `document_json` | JSONB | 编辑状态 |
| `version` | BIGINT | 乐观并发版本 |
| `created_at` | TIMESTAMPTZ | 创建时间 |
| `updated_at` | TIMESTAMPTZ | 更新时间 |

为 `image_assets` 增加可空字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `parent_asset_id` | UUID | 本次成品的直接来源 Asset |
| `edit_document_id` | UUID | 生成该成品的编辑文档 |
| `asset_origin` | TEXT | `generated/uploaded/edited/ai_edited` |

首阶段单个输出只记录一个直接来源。未来支持多素材合成时，再引入多对多 derivation 表。

### 11.3 API

```text
POST   /api/v1/image-edit-documents
GET    /api/v1/image-edit-documents/:id
PUT    /api/v1/image-edit-documents/:id
POST   /api/v1/image-edit-documents/:id/exports
POST   /api/v1/image-edit-documents/:id/ai-expand
GET    /api/v1/tasks/:taskId
GET    /api/v1/tasks/:taskId/events
POST   /api/v1/tasks/:taskId/cancel
POST   /api/v1/tasks/:taskId/retry
```

AI 扩图复用现有 Task 状态机、SSE、取消和重试接口，不建立第二套任务基础设施。阶段 3 需要把当前仅支持会话消息上下文的 `image_tasks` 泛化为两种合法来源：

- 会话任务：保留 `conversation_id/user_message_id/assistant_message_id`；
- 编辑器任务：使用 `edit_document_id`，不创建伪造的会话消息。

数据库通过约束保证任务只能属于其中一种来源。现有会话任务字段在历史数据中保持不变，相关查询需要显式处理编辑器任务的可空会话字段。

创建文档：

```json
{
  "sourceAssetId": "uuid",
  "mode": "canvas"
}
```

保存文档：

```json
{
  "version": 3,
  "schemaVersion": 1,
  "document": {}
}
```

服务端返回新的 `version`。版本冲突时返回明确的 `409`，不得静默覆盖其他页面保存的更新。

服务端必须对 `document_json` 执行版本化 Schema 校验，并验证文档引用的所有 Asset 都属于当前用户。不能只依赖 TypeScript 类型或前端校验。

导出使用 multipart：

- `file`：浏览器确定性渲染的输出文件；
- `documentVersion`：导出所基于的文档版本；
- `format`：PNG/JPEG/WebP；
- `width`、`height`：客户端声明的目标尺寸。

服务端解码文件并核对真实格式和宽高，校验通过后保存新 Asset。客户端声明与真实文件不一致时拒绝保存。

## 12. 高清导出

### 12.1 导出流程

1. 通过受认证 Asset Content 接口读取原始文件；
2. 使用 `createImageBitmap` 或原始 `HTMLImageElement` 解码；
3. 创建目标真实尺寸的 Canvas 或 OffscreenCanvas；
4. 根据文档坐标绘制背景；
5. 使用 `drawImage` 的 source/destination 参数绘制原图；
6. 应用旋转、翻转和裁剪变换；
7. 编码为目标格式；
8. 上传至导出接口；
9. 服务端校验并持久化为新 Asset。

### 12.2 质量规则

- Crop：源区域与目标区域一一对应，不进行缩放；
- Cover/Contain/Free：仅在目标尺寸确实不同时重采样；
- 下采样使用浏览器高质量平滑；质量不足时再评估 `pica` 或服务端 Lanczos；
- JPEG 默认质量维持现有 `0.95`，透明背景不可选 JPEG；
- PNG 不设置有损质量参数；
- 导出结束后及时释放 Bitmap、Canvas 和 Object URL。

### 12.3 大图限制

沿用并统一当前限制：

- 单边最小 16px；
- 编辑器首阶段单边最大 8192px；
- 总像素最大 33,554,432；
- 服务端 Asset 解码仍执行更高层安全上限。

4K 图片的 RGBA 内存约为数十 MB。导出过程中避免同时保留多个全尺寸 Canvas；预览使用同一个原始解码对象和缩小的显示视口。

## 13. 状态管理

编辑器状态分为四类：

| 状态 | 是否保存到文档 | 示例 |
|---|---:|---|
| 文档状态 | 是 | 画布、图片变换、裁剪、背景 |
| 选择状态 | 否 | 当前选中元素、当前工具 |
| 视口状态 | 否 | 缩放、平移、适应窗口 |
| 请求状态 | 否 | 保存中、导出中、AI 任务中 |

文档更新必须通过明确命令进入，禁止 Konva 节点成为唯一真实状态。Konva 是文档状态的渲染结果；交互完成后把变换写回文档 Store。

建议命令：

```text
SetCanvasSize
SetFitStrategy
MoveImage
ScaleImage
RotateImage
SetCropRect
SetBackground
ResetDocument
```

## 14. 性能与可用性

### 14.1 性能

- 指针移动通过 `requestAnimationFrame` 合并渲染；
- 拖动期间更新 Konva 节点，结束时一次性写入历史；
- 文本输入直接更新草稿，合法后下一帧更新画布；
- 自动保存只在空闲且文档稳定时触发；
- 原图按需解码，切换 Asset 时释放旧资源；
- 参考线和控制点使用独立轻量 Layer；
- 不在响应式深层对象中保存 Canvas、ImageBitmap 等不可序列化实例。

### 14.2 可访问性

- 所有按钮和输入有明确中文标签；
- 工具不能只依赖颜色表达状态；
- 支持键盘移动选中元素；
- 支持 `Ctrl/Cmd + Z`、`Ctrl/Cmd + Shift + Z`、`Esc`、`Delete`；
- 尊重 `prefers-reduced-motion`；
- 错误信息与对应字段关联；
- 导出和 AI 任务提供真实状态，不显示虚假百分比。

## 19. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Konva 文档状态与节点状态双源 | 撤销、保存和导出不一致 | 文档 Store 是唯一真实状态，节点只负责交互渲染 |
| 4K/8K Canvas 内存过高 | 页面卡顿或崩溃 | 单实例导出、及时释放、像素上限、必要时 Worker/服务端导出 |
| 浏览器导出差异 | 不同浏览器颜色或编码差异 | 固定测试素材、服务端解码校验、关键格式回归 |
| AI Provider 能力不一致 | 扩图尺寸或蒙版失效 | 能力门控、Adapter 明确声明、确定性后处理 |
| 一次性替换旧功能 | 回归范围过大 | 新路由并行实现，阶段 1 验收后切入口 |
| 功能膨胀成通用设计平台 | 复杂度失控 | 优先生成图成品化，不做与核心工作流无关的功能 |
| 第三方依赖升级 | API 变化或包体增加 | 锁定版本、封装最小适配层、保留导出核心自研 |

## 20. 依赖选择

### 20.1 采用

- Konva：编辑器场景图、图层、变换、裁剪和交互；
- Vue 3 / TypeScript：保持现有前端技术栈；
- Naive UI：保持现有表单、弹窗和反馈风格；
- 原生 Canvas/OffscreenCanvas：确定性导出；
- 现有 Local/S3 Asset 层：原图和导出成品持久化。

### 20.2 暂不采用

- Fabric.js：能力完整但本阶段无需同时引入第二套 Canvas 引擎；
- Filerobot Image Editor：快速但深度交互和状态模型受第三方约束；
- TUI Image Editor：维护活跃度不足以作为新核心；
- miniPaint：完整编辑器过重；
- Advanced Cropper：仍以单图 Cropper 为中心，不能解决独立成品画布问题；
- InvokeAI/ComfyUI 前端：仅参考 AI 画布，不嵌入其完整 UI。

引入依赖前必须再次核验当前版本、许可证、包体和 Vue 兼容性，并将确切版本写入实现提案或提交说明。
